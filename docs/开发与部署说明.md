# 开发与部署说明

> 完整约定见 `docs/计划初稿.md` 第 15 章。本文是落地后的实操说明。

## 一、本地开发

### 1. 启动基础设施（MySQL 8.0 + Redis）

```bash
cp .env.example .env          # 按需修改密码
docker compose up -d mysql redis
```

> 本机 phpstudy 已占用 3306，MySQL 映射到宿主 `3307`，Redis 映射 `6379`。

### 2. 后端

```bash
cd server
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp ../.env.example .env         # 后端本地开发读取 server/.env（字段名与根 .env 一致）
alembic upgrade head            # 仅经 Alembic 初始化表结构，应用启动不隐式建表
# 初始化管理员 + 演示数据（幂等；密码经环境变量注入，禁止写死）
ADMIN_SEED_PASSWORD=你的密码 python -m scripts.seed
uvicorn app.main:app --reload   # http://localhost:8000
```

- 存活探针 `GET /health`；就绪探针 `GET /health/ready`（校验 MySQL + Redis）。
- 接口文档 `http://localhost:8000/docs`（生产环境自动关闭）。
- 管理员账号 `admin`（密码为 seed 时的 `ADMIN_SEED_PASSWORD`）；普通用户通过注册接口创建。

### 3. 前端

```bash
cd admin-web && npm install && npm run dev   # 管理端 http://localhost:5173
cd user-web  && npm install && npm run dev   # 用户端 http://localhost:5174
```

Vite 已把 `/api`、`/uploads`、`/ws` 代理到 `http://localhost:8000`。

### 4. 测试

```bash
cd server
pytest          # 使用独立 SQLite 测试库，不触碰开发/生产库
```

## 二、Docker Compose 一键部署（演示 / 生产）

```bash
cp .env.example .env            # 修改数据库密码、JWT 密钥、APP_ENV、ADMIN_SEED_PASSWORD
docker compose up -d --build
```

- 用户端：`http://localhost:${USER_WEB_PORT:-80}`
- 管理端：`http://localhost:${ADMIN_WEB_PORT:-81}`

**镜像与编排：**

| 服务 | 镜像 | 说明 |
|---|---|---|
| `mysql` | mysql:8.0 | 主库，`mysql_data` 持久卷，健康检查 |
| `redis` | redis:7-alpine | 缓存/购物车，AOF 持久化，健康检查 |
| `backend` | 自建 `deploy/Dockerfile.server` | 启动时自动 `alembic upgrade head`，非生产环境幂等 seed，单实例 Uvicorn |
| `web` | 自建 `deploy/Dockerfile.web` | 多阶段构建双前端，Nginx 托管 + 反代 `/api`、`/uploads`、`/ws` |

**关键说明：**

- 后端容器内 `MYSQL_HOST=mysql`、`REDIS_HOST=redis`，使用服务名访问依赖（compose 内网）；宿主的 `3307`/`6379` 映射仅便于本地调试。
- 上传目录由 `uploads_data` 命名卷持久化挂载到 `/app/uploads`，容器重启图片不丢。
- 演示图片随代码入库于 `server/seed_data/images/`，seed 时幂等复制到 `uploads/`，保证图片 URL 可访问。
- Nginx 配置了 WebSocket `Upgrade` 头与 SPA history 回退；`client_max_body_size 10m` 覆盖 5MB 图片上传。
- 仅暴露 `web`（80/81）对外，MySQL/Redis 不直接暴露公网（生产建议注释掉其 `ports` 段）。

## 三、生产部署最低要求

1. 使用生产 `.env`：`APP_ENV=production`、`APP_DEBUG=false`，更换强随机 `JWT_SECRET_KEY` 与数据库密码。
2. 生产环境 `APP_ENV=production` 时不自动 seed、不创建默认管理员、关闭 Swagger；管理员账号另行安全创建。
3. Nginx `server_name` 改为实际域名，启用 HTTPS/WSS（WebSocket 生产必须 WSS）。
4. 定期备份 MySQL（`mysql_data` 卷）与 `uploads_data` 卷。
5. **支付边界**：V1 仅提供模拟支付（页面/接口均标注"模拟支付"），不接真实微信/支付宝；面向真实用户开放前须先完成真实支付合规设计。
6. 定时关单为单实例 APScheduler；如需多副本部署，须改为独立 scheduler 进程或分布式锁（V1 不涉及）。

## 四、可重复启动与幂等

- 空环境仅凭 `alembic upgrade head` 初始化；应用启动不调用 `create_all()`。
- `seed` 幂等：重复执行不产生重复演示数据；管理员密码未设置时跳过管理员创建。
