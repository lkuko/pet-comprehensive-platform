# 项目计划与结构

> 完整基线见 `docs/计划初稿.md`（唯一开发依据）。本文是当前实施状态的简表。

## 架构

- 前后端分离、模块化单体应用。
- 一个 FastAPI 后端，按业务模块和用户端/管理端分包；不拆微服务。
- 两个前端应用：`admin-web`（管理端）、`user-web`（用户端），共用同一后端 API。

## 后端分层

```
api/（Router，只做参数接收与依赖注入，不写业务）
  → services/（业务规则与事务边界）
    → repositories/（可复用查询）
      → models/（ORM）
schemas/（Pydantic 输入输出，与 ORM 分离）
core/（配置、数据库、Redis、安全、依赖、异常、日志）
common/（统一响应、分页、枚举、常量）
tasks/、websocket/、storage/、utils/
```

依赖方向单向：Router → Service → Repository/Session；Schema 不依赖 Router；Model 不依赖 Service。

## 工程纪律（不可妥协）

1. 配置分环境，密钥走环境变量。
2. 表结构只经 Alembic 迁移，禁止启动时 `create_all()`。
3. 业务规则以后端为唯一权威，写操作明确事务边界。
4. 核心并发流程（领养审核、预约容量、订单库存/支付/关单）必须有 Service 层测试与 API 集成测试。
5. 每个模块完成需满足：迁移 + Schema + Service + Router + pytest + 前端联调 + 文档更新。
